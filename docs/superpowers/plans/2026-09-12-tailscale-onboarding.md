# Tailscale 설치·연결 안내 개선 작업 계획

> **For agentic workers:** 구현할 때 `superpowers:executing-plans` 또는 독립 작업에 맞는 `superpowers:subagent-driven-development`를 사용한다. `AGENTS.md`의 M3 우선 코딩·작은 작업 분할·검토 정책을 따른다.

**Goal:** 사용자가 별도로 설치 방법을 검색하지 않고 RemoteCodex 안에서 Tailscale 설치, 로그인, 원격 연결 준비를 완료하도록 안내한다.

**Architecture:** 로컬 Tauri 백엔드가 설치 감지와 공식 설치 프로그램 실행을 담당한다. Svelte UI는 진행 상태와 다음 행동을 안내하고, 기존 Tailscale Serve 소유권·설정 보존 로직을 재사용한다. 터미널·미디어 프로토콜은 이번 개선에서 변경하지 않는다.

**Tech Stack:** Rust/Tauri, Svelte/TypeScript, Windows 공식 설치 프로그램, 기존 Tailscale CLI 연동.

**상태:** 구현 및 로컬 검증 완료. 실제 설치·로그인과 기존 설치 환경 보존 실검증은 남아 있다. [검증 기록](../../test-results/tailscale-onboarding-2026-09-12/README.md)을 확인한다. 표준 경로를 매 요청마다 다시 검사하여 PATH 미반영 설치를 감지하며, 임의 비표준 registry PATH 변경의 동적 반영은 지원하지 않는다.

## 먼저 지켜야 할 테스트 경계

- 사용자는 다른 PC에서 현재 버전을 테스트 중이라고 알렸다. 그 PC의 실행 버전·진행 상황은 별도로 확인해야 하며, 이 PC의 결과로 대신하지 않는다.
- 다른 PC의 현재 테스트는 기존 실행 파일과 설정으로 계속한다. 이 작업 때문에 Tailscale 업데이트, Serve 변경, Agent 재시작을 자동 실행하지 않는다.
- 구현은 별도 브랜치/작업 공간에서 진행하고, 테스트 중인 바이너리·프런트엔드 서비스 경로와 분리한다. 실행 중인 Agent가 서빙하는 `web_dir`도 빌드로 덮어쓰지 않는다.
- Git에 소스가 올라간 것과 실행 중인 제품에 적용된 것은 구분한다. 새 버전을 설치·재시작하거나 서비스 중인 자산을 바꾸면 테스트 조건이 달라질 수 있다.
- 적용 전 기존 테스트의 소스 커밋, 실행 파일 해시, Tailscale 버전, 설정, 실행 시간을 기록한다. 서로 다른 빌드의 결과를 하나의 연속 soak 통과로 합치지 않는다.

## 현재 문제와 확인할 코드

`apps/web/src/HostSettings.svelte`는 미설치 시 경고만 표시하며, 사용자가 설치와 로그인 방법을 직접 찾아야 한다. `apps/desktop/src-tauri/src/tailscale.rs`의 `SystemRunner`는 `tailscale.exe`라는 이름으로 실행한다. 표준 설치 경로와 앱 실행 후 변경된 PATH까지 고려하는 감지가 필요하다.

주요 파일:

- `apps/web/src/HostSettings.svelte`: 기존 호스트 설정과 Serve UI.
- `apps/web/src/App.svelte`: 호스트/클라이언트 선택과 초기 안내.
- `apps/desktop/src-tauri/src/tailscale.rs`: CLI 실행, 상태 검사, Serve 소유권과 설정 보존.
- `apps/desktop/src-tauri/src/main.rs`: 로컬 Tauri 명령 등록과 기존 설정 적용.
- 신규 `apps/desktop/src-tauri/src/tailscale_setup.rs`: 설치 감지·설치 실행·로그인 상태 전담 모듈로 분리하는 안.
- 신규 `apps/web/src/TailscaleSetup.svelte`: 단계별 설치·연결 안내 UI로 분리하는 안.

신규 파일명은 구현 시 기존 구조를 확인해 확정한다. 설치 권한을 원격 웹 페이지나 프리뷰에 노출하지 않는다.

## 목표 사용자 흐름

1. **원격 연결 준비하기** 버튼을 누른다.
2. 이미 설치됐으면 기존 설치를 사용한다. 없으면 공식 설치 파일 다운로드·검증·실행으로 이어진다.
3. 필요한 Windows 설치 승인과 브라우저 계정 로그인은 사용자가 수행한다. 앱은 완료 여부를 확인해 다음 단계로 이동한다.
4. 호스트 PC는 원격 접속을 켜는 범위를 설명하고 기존 소유권 검사를 거쳐 설정한다. 클라이언트 PC에는 호스트용 Serve나 Agent 자동 시작을 켜지 않는다.
5. 연결 준비 완료 여부와 접속 주소를 보여준다. 호스트 주소가 확인되지 않으면 준비 완료로 표시하지 않는다.

기본 화면 상태는 `설치 확인 중`, `설치 필요`, `설치 중`, `로그인 필요`, `연결 설정 필요`, `연결 준비 완료`, `실패/취소`로 구분한다. CLI·Serve·HTTPS 443과 자세한 오류는 고급 설정/진단에서 볼 수 있게 한다. 브라우저·모바일에서는 해당 플랫폼 설치 안내를 제공하며 Windows 설치 기능을 노출하지 않는다.

## 작은 구현 작업

각 작업은 먼저 필요한 실패 사례를 테스트로 재현하고, M3에 관련 파일 1~3개와 하나의 수정 목표를 전달한다. 검토·해당 검사 통과 후 작업 단위로 커밋한다.

### 1. 설치 감지와 상태 계약

- [x] 미설치, 표준 경로 설치, PATH 미반영, CLI 실행 실패, 서비스 미실행을 구분하는 테스트를 작성한다.
- [x] 표준 설치 경로와 실행 가능한 CLI를 검증해 사용한다. 단순 실행 실패를 모두 미설치로 표시하지 않는다.
- [x] UI에 보낼 명시적 상태·실패 이유를 정의하고 감지 테스트를 통과시킨다.

### 2. 공식 설치 프로그램 실행

- [x] 설치 동작은 로컬 사용자의 버튼 실행으로 시작하고 중복 실행을 차단한다.
- [x] 구현 시 공식 배포 URL·지원 아키텍처·배포 방식을 확인한다. 앱이 선택한 설치 버전과 다운로드 출처를 기록한다.
- [x] 다운로드 완료와 공식 배포물 검증을 확인한 뒤 실행한다. HTTPS만으로 실행 파일의 신뢰성을 판정하지 않으며 Windows 서명/공식 검증 정보를 확인한다.
- [x] 다운로드 실패, 검증 실패, 설치 취소, 관리자 승인 거부, 재부팅 필요를 구분한다. 사용자 입력으로 임의 URL·명령을 실행하는 API를 만들지 않는다.
- [x] 설치 후 CLI·서비스 상태를 다시 확인한다. 기존 설치를 발견하면 자동 재설치·업데이트하지 않는다.

### 3. 로그인과 연결 상태

- [x] 설치 완료와 로그인 완료를 별도 상태로 처리한다.
- [x] 공식 로그인 흐름으로 연결하고, 제한된 주기·시간 내에 상태를 다시 검사한다. UI를 닫으면 불필요한 polling을 정리한다.
- [x] 로그인 취소·시간 초과·서비스 오류를 재시도 가능한 상태로 표시한다. 계정 인증을 우회하거나 인증 키를 소스·로그·프로세스 인자에 넣지 않는다.

### 4. 초기 설정 UI와 기존 Serve 연결

- [x] 설치·로그인·연결 단계를 UI에 연결하고 각 상태에 필요한 행동 하나를 명확히 표시한다.
- [x] 기존 Serve 소유권 검사와 동의 범위를 유지한다. 다른 서비스의 443 설정, 기존 tailnet 계정·ACL·라우팅 설정을 덮어쓰지 않는다.
- [x] 설정 때문에 Agent 재시작이 필요하면 상태를 보여주고 실행 중인 PTY를 자동 종료하지 않는다.
- [x] 설치됨/미설치/로그인 필요/설정 충돌/완료/취소 상태를 검증하고 기본 화면에서 기술 용어를 줄인다.

### 5. 통합 검증과 배포 기록

- [x] 개발 PC의 기존 VPN 설정을 바꾸지 않는 감지·상태 테스트부터 실행한다.
- [ ] 설치 허용된 별도 Windows 테스트 환경에서 미설치→설치→로그인→연결 흐름과 취소·재시도를 확인한다.
- [ ] 이미 설치된 환경에서 재설치 없이 감지되는지, 기존 계정과 Serve 설정이 보존되는지 확인한다.
- [x] 변경한 Rust/Tauri 모듈 테스트와 `npm run check:web`, `npm run build:web`를 실행한다. 네이티브 UI 확인은 Tauri CLI 배포 빌드로 한다.
- [x] 새 실행 파일/패키지의 커밋·해시와 검증 범위를 기록하고 `IMPLEMENTATION_STATUS.md`, `ACCEPTANCE_MATRIX.md`, 사용자 안내를 갱신한다.

## 무엇을 다시 테스트해야 하나

| 실제 변경 | 필요한 검증 |
|---|---|
| 이 문서만 커밋 | 문서·링크 확인. 실행 중인 테스트를 재시작할 필요 없음 |
| 설치 감지·설정 마법사 UI/백엔드 추가 | 감지·설치·로그인·취소·기존 설정 보존, 새 빌드에서 기존 연결이 유지되는지 확인 |
| Tailscale 자체 버전 변경 | 원격 연결·재연결·프리뷰·영상 등 사용하는 네트워크 경로와 성능 영향 확인 |
| Serve·포트·주소·권한·ICE 정책 변경 | 영향을 받는 인증·접속·프리뷰·영상 경로를 실제 두 PC에서 재검증 |
| Agent/PTY 코드 변경 또는 테스트 중 Agent 재시작 | 관련 터미널 회귀 검사. 진행 중이던 연속 실행 검사는 중단으로 기록하고 새 실행과 분리 |

설치 안내 개선만으로 기존 모든 테스트가 무효가 되지는 않는다. 반대로 네트워크나 실행 프로세스가 바뀌었는데 이전 검사 결과를 새 버전 전체의 통과 근거로 쓰지 않는다.
